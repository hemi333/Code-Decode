# 2주차 · Tool Calling Agent 확장

1주차에 루프를 한 번 돌렸습니다. 도구는 하나였고, 한 번 불렀고, 실패하지 않았습니다.
현실은 그렇지 않습니다. 이번 주는 그 셋을 다 깨뜨립니다.

    도구가 여러 개일 때     → 병렬
    한 도구의 결과가 다음 도구의 인자일 때  → 연쇄
    도구가 실패할 때        → is_error
    모델이 같은 걸 반복할 때 → 예산
    질문이 이어질 때        → 세션

---

## 이번 주 시나리오

> "fixtures 폴더에서 가장 긴 파이썬 파일이 뭐야?"

```
list_files("*.py")          모델은 뭐가 있는지 모른다. 먼저 물어봐야 한다.
      ↓
read_file × 3               한 번에 세 개. 그중 하나는 없는 파일이다.
      ↓
count_lines × 2             또 병렬.
      ↓
답
```

이 질문 하나에 병렬, 연쇄, 실패가 다 들어 있습니다.
1주차 체크포인트였던 "도구를 2회 이상 연속 호출" 도 여기서 충족됩니다.

## 이번 주 체크포인트

> 도구를 2회 이상 연속 호출하는 시나리오가 동작한다

`check.py agent` 가 통과하면 됩니다. 다만 그게 끝이 아닙니다.

**`read_file` 의 경로 검사가 이번 주에서 제일 중요합니다.**
도구의 인자는 모델이 만든 값이고, 모델은 사용자 입력과 (나중에는)
인터넷에서 긁어온 문서에 영향을 받습니다. 그러니까 신뢰할 수 없는 입력입니다.

이름에 `/` 나 `..` 가 있는지 보는 것만으로는 부족합니다.
직접 뚫어보세요.

```bash
ln -s ../agent.py fixtures/sneaky.py
python -c "import tools; print(tools.dispatch('read_file', {'name':'sneaky.py'}))"
rm fixtures/sneaky.py
```

막지 못했다면 `CHECKPOINT.md` 의 D11 을 읽고 다시 짜세요.

## 1주차와 달라진 곳

1주차 `step4_loop.py` 를 옆에 열어두고 비교하세요.
어디가 그대로이고 어디가 달라졌는지 보는 게 공부의 절반입니다.

| | 1주차 | 2주차 |
| --- | --- | --- |
| 구조 | 함수 `run()` | 클래스 `Session` |
| 상태 | 함수가 끝나면 사라짐 | 객체가 들고 있음 |
| 도구 | 1개 | 3개 |
| tool_use 처리 | 사실상 1개 | N개 |
| 실패 | 생각 안 함 | `is_error` |
| 종료 | `MAX_TURNS` | `MAX_TURNS` + `MAX_REPEATS` |

**루프의 뼈대는 바뀌지 않았습니다.** 호출 → `stop_reason` 확인 → 도구 실행 →
결과 붙이고 다시 호출. 6주차 Code Decode Agent 도 이 구조 그대로입니다.
