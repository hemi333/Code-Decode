# 1주차 · 2단계 답 — 응답을 해부한다

## 1. 도구를 붙였을 때 stop_reason 은 무엇으로 바뀌는가

`end_turn` → `**tool_use**` 로 바뀐다.


| 값          | 의미                                          | 우리가 할 일             |
| ---------- | ------------------------------------------- | ------------------- |
| `end_turn` | 모델이 할 말을 다 하고 스스로 멈췄다. **완결**               | 없다. 한 턴이 끝난 것       |
| `tool_use` | 도구를 부르려고 멈췄다. 결과를 받아야 말을 이어갈 수 있다. **일시정지** | 도구를 실행해 결과를 돌려줘야 한다 |


핵심은 **둘 다 정상 종료인데 "끝났다"의 뜻이 다르다**는 것이다. `end_turn` 은 마침표고
`tool_use` 는 쉼표다. 모델이 공을 우리한테 넘기고 기다리는 상태다.

1단계에서 본 `max_tokens` 까지 놓고 보면 세 가지가 전부 "응답이 끝났다" 인데
의미가 전부 다르다. 그래서 `stop_reason` 을 안 보고 짜면 안 된다.

## 2. 블록이 여러 개 오는 경우 — 재현했다

같은 도구를 붙이고 질문만 바꿔서 5회씩 돌렸다. (`claude-sonnet-5`, `max_tokens=512`)

```
질문 A: "지금 이 컴퓨터의 파이썬 버전이 뭐야?"        (긴 description)
  5/5   blocks=1   ['tool_use']

질문 B: "지금 이 환경 좀 알려줘. 왜 그걸 확인해야 하는지도 같이 설명해줘."
  5/5   blocks=3   ['thinking', 'text', 'tool_use']
                             ↑ "지금 실행 환경 정보를 확인해볼게요."

질문 A 를 그대로, description 만 한 줄로 줄였을 때
  2/5   blocks=2   ['thinking', 'tool_use']
  3/5   blocks=1   ['tool_use']
```

같은 코드, 같은 도구인데 블록 개수가 1 → 2 → 3 으로 흔들린다. **질문이 설명을
요구하면 모델은 말도 하고 도구도 부른다.** 그때 `text` 와 `tool_use` 가 한 응답 안에
같이 온다.

### content 가 왜 리스트인가

**한 번의 응답 안에 성격이 다른 산출물이 여러 개 들어오기 때문이다.**

- `text` — 사람이 읽을 말
- `tool_use` — 기계가 실행할 명령
- `thinking` — 모델이 답하기 전에 스스로 생각한 흔적

이 셋은 **처리 주체가 다르다.** `text` 는 화면에 뿌리고, `tool_use` 는 함수를 실행하고,
`thinking` 은 보통 버린다. 문자열 하나로 뭉쳐서 왔다면 우리가 다시 파싱해서 갈라내야
한다. 리스트로 오니까 `block.type` 으로 분기만 하면 된다.

결정적으로 — `**tool_use` 블록은 한 응답에 여러 개 올 수 있다.** 도구 3개를 동시에
부르는 병렬 호출이 기본 동작이다. 리스트가 아니면 애초에 표현이 안 되는 구조다.

### 1단계에서 만난 문제가 여기서 반복된다

`response.content[0].text` 는 위 B 케이스에서 0번이 `thinking` 이라 터진다.
1단계에서 `AttributeError: 'ThinkingBlock' object has no attribute 'text'` 를 만나
고친 그 대목 (커밋 `1807735`) 이 그대로 다시 온 것이다.
**'몇 번째 블록'이 아니라 'type 이 무엇인지'로 고른다** — 이 규칙은 예외가 없다.

## 3. 멈춘 대화를 어떻게 잇는가

지금 상태는 **"모델이 python_env 를 부르겠다고 선언만 했고, 아무도 실행하지 않았다"** 다.
이어가려면 네 가지를 해야 한다.

1. **모델의 응답을 `messages` 에 기록한다.** API 는 stateless 라 다음 요청에 전체
 history 를 다시 보내야 한다. `{"role": "assistant", "content": response.content}`
 를 **통째로** 넣는다. 텍스트만 뽑아 넣으면 `tool_use` 블록의 `id` 가 사라진다.
2. **도구를 우리가 실제로 실행한다.** `block.name` 을 보고 진짜 파이썬 함수를 부른다.
 모델은 코드를 실행하지 않는다. **실행 주체는 언제나 우리다.** 모델이 한 일은
 "이 이름의 도구를 이 인자로 불러달라"고 말한 것뿐이다.
3. **결과를 `tool_result` 로 돌려준다.** `block.id` 를 `tool_use_id` 에 넣어 짝을 맞춘다.
 그리고 **role 은 `"tool"` 이 아니라 `"user"`** 다.
4. **다시 호출한다.** 이번엔 `stop_reason` 이 `end_turn` 으로 끝나며 최종 답이 나온다.

```python
messages.append({"role": "assistant", "content": response.content})
messages.append({"role": "user", "content": [{
    "type": "tool_result",
    "tool_use_id": block.id,          # 이 id 로 짝을 맞춘다
    "content": json.dumps(실제_실행_결과),
}]})
response = client.messages.create(..., messages=messages, tools=[...])
```

여기서 나오는 것 두 가지.

**첫째 — 도구를 한 번 쓰는 대화는 API 호출이 2번이다.** (체크포인트 C9)
"도구를 쓴다" 는 것은 왕복이 한 번 더 는다는 뜻이고, 그만큼 돈과 지연이 는다.

**둘째 — `stop_reason == "tool_use"` 인 동안 위 네 단계를 반복하는 것,
그게 4단계 에이전트 루프의 전부다.** 루프는 결국 `messages` 에 계속 append 하는 일이다.
1단계 3번에서 적은 것과 정확히 같은 이야기다.

## 4. description 을 한 줄로 줄이면 — 조건부로 안 부른다

`"환경 정보를 반환한다."` 한 줄로 줄여서 돌렸다.
(질문마다 3~5회, `claude-sonnet-5`)


| 질문                       | 긴 description | 한 줄 description |
| ------------------------ | ------------- | --------------- |
| "지금 이 컴퓨터의 파이썬 버전이 뭐야?"  | 5/5 호출        | **5/5 호출**      |
| "지금 pandas 깔려 있어?"       | 3/3 호출        | **3/3 호출**      |
| "내 개발 환경 점검 좀 해줘"        | 3/3 호출        | **3/3 호출**      |
| **"파이썬 버전 확인하는 방법 알려줘"** | **1/3 호출**    | **0/3 호출**      |
| "파이썬에서 리스트를 정렬하는 법 알려줘"  | 0/3 호출        | 0/3 호출          |


### 언제 안 부르는가

- **질문이 명백하면 description 이 짧아도 부른다.** "지금 이 컴퓨터의", "지금 pandas"
처럼 질문 자체가 로컬 상태를 가리키면 한 줄짜리 설명으로도 도구를 찾아낸다.
줄였다고 무조건 안 부르는 게 아니다.
- **질문이 애매해지는 순간 갈린다.** "파이썬 버전 확인하는 **방법**" 은 일반 지식
질문으로도, 로컬 조회로도 읽힌다. 여기서 긴 description 은 1/3 을 건졌고 한 줄짜리는
0/3 이었다. `"'지금 이 환경'에 대해 물으면 추측하지 말고 이 도구를 부른다"` 는
문장이 애매한 질문을 도구 쪽으로 밀어준 것이다.
- **무관한 질문("리스트 정렬법")은 어느 쪽도 안 부른다.** 이건 정상이다. description 을
잘 썼는데 무관한 질문에 도구를 부른다면 그게 오히려 버그다.

즉 **description 의 효과는 애매한 경계에서만 드러난다.** 명백한 질문으로만 테스트하면
description 을 아무리 망쳐놔도 잘 되는 것처럼 보인다. 이게 함정이다.

### description 은 문서인가 프롬프트인가 (체크포인트 C10)

**프롬프트다.**

문서라면 사람만 읽고 동작은 안 변해야 한다. 그런데 실제로는 같은 모델·같은 질문에서
호출률이 1/3 → 0/3 으로 내려갔다. **description 은 모델의 의사결정 입력이고, 호출
여부를 결정하는 유일한 근거다.** 모델은 함수 이름의 속뜻도, 구현 코드도, 우리 의도도
못 본다. 본 것은 그 딕셔너리 하나뿐이다.

그래서 description 에는 **무엇을 하는지**보다 **언제 불러야 하는지**를 쓴다.
`"환경 정보를 반환한다"`(무엇) 보다 `"'지금 이 환경'에 대해 물으면 추측하지 말고 부른다"`(언제) 가 실제로 행동을 바꿨다.

## 실행 기록 (2단계)

`step2_anatomy.py` 는 그대로 두고, 별도 스크립트로 같은 도구·같은 모델에 조건만 바꿔
반복 호출했다.

### 원본 그대로 (도구 안 붙임 / 붙임)

```
질문: 지금 이 컴퓨터의 파이썬 버전이 뭐야?

도구 안 붙임 → stop_reason: end_turn   블록 1개  ['text']
               "저는 사용자의 컴퓨터에 직접 접근할 수 없어서..." + 확인 방법 안내

도구 붙임    → stop_reason: tool_use   블록 1개  ['tool_use']
               id    : toolu_01Aw7w13f7Nvq1Yg2FReGCcD
               name  : python_env
               input : {}
```

도구가 없을 때 모델은 **버전을 지어내지 않고 모른다고 했다.** 체크포인트 A3 의
"지어냈다면 모델의 결함인가 우리가 잘못 물어본 것인가" 에 대해서는 — 우리 잘못이다.
알 수 없는 것을 물어놓고 알아맞히기를 기대한 것이고, 그래서 도구를 주는 것이다.

### 반복 실험 (5회 × 조건)

```
A. 긴 description / "지금 이 컴퓨터의 파이썬 버전이 뭐야?"
   tool_use ×5,  blocks=1  ['tool_use'] ×5

B. 긴 description / "지금 이 환경 좀 알려줘. 왜 그걸 확인해야 하는지도 같이 설명해줘."
   tool_use ×5,  blocks=3  ['thinking', 'text', 'tool_use'] ×5

C. 한 줄 description / 질문 A 와 동일
   tool_use ×5,  blocks=2 ['thinking','tool_use'] ×2 / blocks=1 ['tool_use'] ×3

D. 한 줄 description / "파이썬에서 리스트를 정렬하는 법 알려줘"
   도구 호출 0회. blocks=1 ['text'] ×3

E. 긴 description / 질문 D 와 동일
   도구 호출 0회. blocks=2 ['thinking','text'] ×3
```

D·E 의 `stop_reason` 은 `end_turn` 이 아니라 `max_tokens` 로 찍혔다. 도구를 안 부르고
텍스트로 답하다가 상한(512/300)에 걸려 잘린 것이다. **"도구를 안 불렀다"와 "잘렸다"는
별개의 사실인데 `stop_reason` 한 값에 겹쳐 보인다.** 도구 호출 여부는 `stop_reason`
말고 블록 type 으로 세는 게 맞다.

## 겪은 문제와 해결 (2단계)

1. `**blocks=1` 만 보고 "content 가 리스트일 필요가 없다"고 넘길 뻔했다.** 기본 질문
 ("파이썬 버전이 뭐야?") 으로는 5번을 돌려도 계속 `['tool_use']` 하나만 왔다.
 질문에 "왜 그런지도 설명해줘" 를 붙이고 나서야 `['thinking','text','tool_use']`
 3개짜리가 나왔다. → **여러 번 돌리는 것만으로는 부족하고, 조건을 바꿔야 나온다.**
2. **description 실험을 명백한 질문으로만 해서 차이가 안 보였다.** "지금 이 컴퓨터의"
 로 물으면 한 줄 설명으로도 5/5 를 부른다. 애매한 질문("~하는 **방법** 알려줘")을
 넣고서야 1/3 vs 0/3 이라는 차이가 드러났다. → **프롬프트의 효과는 경계에서 측정한다.**
3. **콘솔 출력이 전부 깨져서 결과를 못 읽었다.** Windows 콘솔 기본 코드페이지 문제.
 판정에 필요한 건 한글 본문이 아니라 `stop_reason` 과 블록 type 이라, 본문 대신
 `[b.type for b in r.content]` 만 찍게 바꿔서 해결했다.
