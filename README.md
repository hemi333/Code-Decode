# 1주차 · LLM API와 Tool Calling 구조

이번 주에 만드는 것은 **에이전트 루프**입니다. 20줄 남짓이고, 앞으로 6주 동안
이 구조는 바뀌지 않습니다. 도구가 늘고 프롬프트가 길어질 뿐입니다.

그래서 이번 주만큼은 라이브러리에 맡기지 않고 손으로 짭니다.

---

## 준비

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

cp .env.example .env       # ANTHROPIC_API_KEY 를 채우세요
```

키는 [Claude Console](https://platform.claude.com) 에서 발급합니다.
가입하면 무료 크레딧이 조금 붙고, 이번 주 실습은 그 안에서 끝납니다.
1~4단계를 전부 돌려도 $0.05 를 넘지 않습니다.

---

## 순서

| | 파일 | 상태 | 하는 일 |
| --- | --- | --- | --- |
| 1 | `step1_hello.py` | 완성 | 실행하고, 그 다음 읽는다 |
| 2 | `step2_anatomy.py` | 완성 | `tool_use` 블록을 눈으로 본다 |
| 3 | `step3_tool.py` | **빈칸** | 도구를 하나 정의한다 |
| 4 | `step4_loop.py` | **빈칸** | 루프를 직접 짠다 |

```bash
python step1_hello.py
python step2_anatomy.py

# 3, 4 를 채운 뒤
python check.py 3
python check.py 4
```

**`check.py` 는 API 키 없이 돌아갑니다.** 가짜 클라이언트가 실제 API 와 같은
형식 검사를 하고, 틀리면 어느 빈칸이 문제인지 알려줍니다.

```
실패  대화 형식이 API 규칙에 어긋납니다
      마지막 메시지의 role 이 'tool' 입니다. 도구 결과는 'user' 역할로 보냅니다.
      → 빈칸 4 를 확인하세요.
```

---

## 이번 주 체크포인트

> 모델이 `tool_use` 를 반환하는 걸 눈으로 확인한다

2단계에서 끝납니다. 다만 `check.py` 가 통과했다고 이번 주가 끝난 건 아닙니다.
**`CHECKPOINT.md` 의 질문에 답할 수 있어야** 끝입니다. 코드가 도는 것과
이해한 것은 다릅니다.

특히 이 두 개는 답이 갈릴 수 있으니 모임에서 이야기해보세요.

- 도구 결과의 `role` 이 왜 `"tool"` 이 아니라 `"user"` 인가
- `sorted(GEN_IMAGES_DIR.glob("*.png"))` 에서 모델은 `.glob` 이 무엇인지 알 수 있는가

두 번째 질문이 5주차의 전부입니다.

---

## 모임에서 할 일

1. 1~4단계를 각자 해온 상태로 모입니다.
2. `CHECKPOINT.md` 를 한 문항씩 짚습니다. 한 사람이 답하고 나머지가 반박합니다.
3. `RULES.md` 를 읽고 **스터디 규칙을 확정합니다.** 이게 1주차의 진짜 산출물입니다.
